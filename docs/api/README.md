# API and data contracts (v1)

Source of truth: [`packages/contracts`](../../packages/contracts/src) (zod). Everything in this
folder is generated by `bun run contracts:gen`, and a test fails if it drifts.

- [`openapi.json`](openapi.json): the public read API, also served at `GET /api/v1/openapi.json`.
- [`examples/`](examples): one canonical, schema-validated payload per contract.

## Versioning
- Contracts package: `CONTRACTS_VERSION = 1.0.0`. HTTP routes live under `/api/v1`. Breaking changes bump the major and add `/api/v2`.
- Cross-process payloads carry an explicit tag: `match-request/1`, `match-result/1`, `editorial-facts/1`. Tactical configs carry `schemaVersion: "tactics/N"`.
- The database schema is versioned by migration number (`schema_migrations`, also `GET /api/v1/meta`).

## Integration contracts
| Contract | Purpose | Example |
| --- | --- | --- |
| `MatchRequest` | Seed, pinned sim version, 5 starters per side (slot order GK, DF, DF, MF, FW), controller deployments | [match-request](examples/match-request.json) |
| `MatchResult` | Official score, events, stats, replay URI/sha256/verification, final hash, versions, diagnostics | [match-result](examples/match-result.json) |
| `ControllerDeployment` | `{kind:'tactical', schemaVersion, config}` or `{kind:'scripted', sdkVersion, artifactId}` | in match-request |
| `EditorialFacts` | The only material editorial agents may use: official events, stats, lineups and facts with stable ids for citation | [editorial-facts](examples/editorial-facts.json) |
| `Job` | Durable job: `queued → running → succeeded/failed`, unique idempotency key, attempts, artifact links | [job](examples/job.json) |

Home is always the simulator's `blue` side and away is `red`. Match clocks are **simulator seconds
within a half** (2 × 120 s by default), not real-world minutes.

## Domain tables (`packages/db/migrations/0002_domain.sql`)
`teams`, `players`, `manager_agents`, `editorial_agents`, `seasons`, `season_teams`, `fixtures`,
`tactical_revisions`, `agent_runs`, `matches`, `replay_artifacts`, `compute_transactions`,
`articles`, `jobs`.

Invariants enforced in the database (tested in `packages/db/src/schema.test.ts`):
- Fixtures: no self-play; each ordered pairing once per season (double round robin); one fixture per team per round (trigger).
- Exactly **one match per fixture** (`matches.fixture_id unique`); a `completed` match must carry score, final hash and completion time.
- One replay artifact per match, carrying sha256, engine/SDK versions and verification status.
- Tactical revisions: unique `(team, season, version)`; deployment kind ∈ {tactical, scripted}; only `rejected` revisions may have validation errors.
- Agent runs and jobs: unique idempotency keys.
- Compute ledger in integer micro-USD with sign rules per kind (grant +, reserve −, release +, charge −). Balance = sum.
- Articles: `ai_generated` must be true; `published` requires `published_at`.

## Public read endpoints
| Route | Response |
| --- | --- |
| `GET /seasons/current` | `SeasonResponse` |
| `GET /seasons/{season}/standings` | `StandingsResponse` |
| `GET /seasons/{season}/fixtures` | `FixturesResponse` |
| `GET /seasons/{season}/budget` | `BudgetResponse` |
| `GET /teams`, `GET /teams/{team}` | `TeamListResponse`, `TeamDetailResponse` |
| `GET /matches/{match}` | `MatchDetailResponse` |
| `GET /matches/{match}/replay` | gzip replay file |
| `GET /articles`, `GET /articles/{article}` | `ArticleListResponse`, `ArticleDetailResponse` |
| `GET /journalists`, `GET /journalists/{journalist}` | `JournalistListResponse`, `JournalistDetailResponse` |
| `GET /seasons/{season}/dugout`, `GET /teams/{team}/dugout` | `DugoutResponse`, `TeamDugoutResponse` (contract `dugout/1`) |

**Inside the Dugout (`dugout/1`).** Each manager's season as chapters: *decision* (the tactical revision the match actually used, changes vs. the previous match, lineup in/out, and the manager's stated rationale only when they gave one for that match), *result* (official score, possession, shots) and *reflection* (the post-match lesson). Statuses make gaps explicit: `opening`, `kept`, `new`, `skipped_budget`, `rejected`, `failed`, `pending`; reflections `reviewed`, `skipped_budget`, `failed`, `pending`. Built only from `tactical_revisions`, `matches` and the `lesson`/`summary` strings of manager runs; prompts and other run payloads are never read.

Handlers are implemented by the feature issues (#18 matches/replays, #19 league, #24 budget,
#25 editorial) and must return data that parses with these schemas.
